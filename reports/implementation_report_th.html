ดำเนินการตามแผนที่อนุมัติครบทุกขั้นตอน การแก้ไขที่สำคัญที่สุด (AUD-001) คือการรักษาความแม่นยำของตัวเลข โดยเพิ่มความละเอียดที่แสดงผลเป็น 15 significant digits ให้ตรงกับชั้นรับข้อมูล ทำให้ค่าที่รองรับความยาว 13–15 หลักไม่ถูกปัดเศษอย่างเงียบ ๆ เมื่อกด = ปรับ semantics ของการป้อนข้อมูลให้สอดคล้องกัน ได้แก่ backspace จะคำนวณสถานะโหมดเลขชี้กำลังใหม่เสมอ, การวางค่าติดกับค่าเดิมจะแทรก × โดยนัย, ตัวดำเนินการ binary ระดับบนสุดจะออกจากโหมดเลขชี้กำลัง และ +/- บนเลขยกกำลังจะเปลี่ยนเครื่องหมายของฐาน การคำนวณที่ล้มเหลวจะไม่เปลี่ยน token stream ที่แสดงอยู่

มีการปรับปรุงด้าน Accessibility, storage, PWA และ CI: history drawer จะเป็น inert เมื่อปิด พร้อม CSS visibility fallback; บรรทัดแสดงผลและเมนู clipboard ใช้งานด้วยแป้นพิมพ์ได้; ตรวจสอบประวัติที่บันทึกไว้และจำกัดจำนวน/ขนาดที่ขอบเขต storage; service worker แยก precache ของไฟล์จำเป็นกับไอคอนเสริม โดยไอคอนเสริมล้มเหลวได้โดยไม่ทำให้ติดตั้งล้มเหลว และตอบ 504 อย่างชัดเจนเมื่อ offline; ปุ่มเวอร์ชันจะ reload หลัง worker activate เท่านั้น; ส่วน deploy จะรัน tests และ grep ตรวจความปลอดภัยของ dynamic code ก่อนเผยแพร่ artifact ที่ stage ไว้ใน _site/

ไม่มีการ refactor ที่ไม่เกี่ยวข้อง ไม่มี dependency, build step หรือการเปลี่ยนแปลงด้านรูปลักษณ์ที่ไม่จำเป็น และคง public interfaces ที่แอปกับ tests ใช้อยู่ทั้งหมด การเปลี่ยนพฤติกรรมโดยตั้งใจมีเฉพาะข้อกำหนดที่อนุมัติแล้ว ได้แก่ การออกจากโหมดเลขชี้กำลัง, การเปลี่ยนเครื่องหมายบนเลขยกกำลัง, การวาง × และ orientation ของ manifest

สถานะการตรวจสอบ: node --test tests/*.test.js → ผ่าน 110, ไม่ผ่าน 0 การตรวจ syntax แบบ static, git diff --check, การค้นหา API ที่ห้ามใช้, ความสมบูรณ์ของ precache/ไฟล์, ขนาดไอคอนใน manifest และการซิงก์เวอร์ชันทั้ง 4 ตำแหน่งผ่านทั้งหมด การตรวจบน browser/device ที่ระบุใน §7 ยังต้องดำเนินการด้วยตนเอง

2. คำอธิบายสถานะ

แก้ไขแล้ว มีการแก้ไขพฤติกรรม/โค้ด และครอบคลุมด้วย automated tests ในส่วนที่ทดสอบบน Node ได้

คงผลการตรวจเดิม คงข้อสรุปของ audit ว่าเป็น false positive และเพิ่ม static invariant test เพื่อป้องกันการเปลี่ยนแปลง

ดำเนินการแล้ว — รอตรวจด้วยตนเอง โค้ดดำเนินการเสร็จแล้ว แต่ยังต้องตรวจสอบด้วย browser/device จริง หรือบันทึก performance ผ่าน DevTools

8. ความเสี่ยงที่ยังเหลืออยู่

  • พฤติกรรมที่ต้องตรวจบนอุปกรณ์: touch gestures, focus/trap behavior, native activation และเส้นทางติดตั้ง/อัปเดต PWA พัฒนาตามพฤติกรรม DOM/spec แล้ว แต่ไม่สามารถยืนยันได้ครบถ้วนด้วย Node รายการตรวจด้วยตนเองข้างต้นจึงเป็นเงื่อนไขก่อน release
  • กรณีขอบของ exponent/reciprocal: ลำดับการกระทำแบบสุ่มที่ไม่จำกัดยังอาจทำให้เกิด nested reciprocal/power token flags ที่ผิดปกติบางแบบ ซึ่งมีอยู่ก่อนงานนี้และอยู่นอกประเด็นที่อนุมัติ เส้นทางที่แก้แล้ว (backspace recovery, implicit multiplication, operator exit, sign-on-power) มี deterministic tests ครอบคลุม
  • ความขัดแย้งระหว่างหลายแท็บ: NEW-006 reload รายการที่บันทึกไว้และผ่าน validation แล้ว แต่การเขียนพร้อมกันจาก 3 contexts ขึ้นไปยังอาจใช้หลัก last-write-wins การกำหนดนโยบาย merge เต็มรูปแบบต้องให้ฝ่ายผลิตภัณฑ์พิจารณา
  • storage ที่ใช้ shared origin: localStorage ยังอ่านได้จากแอปอื่นที่ใช้ GitHub Pages origin เดียวกัน (AUD-020) validator ในแอปลดผลกระทบจากข้อมูลผิดรูปแบบ แต่ไม่สามารถแยก origin ได้ วิธีแก้ที่สมบูรณ์คือใช้ dedicated origin
  • Meta CSP: GitHub Pages ไม่สามารถกำหนด custom response headers ได้ จึงยังใช้ frame-ancestors และ reporting ไม่ได้ (AUD-019) การตั้งค่า script-src ไม่เปลี่ยน และไม่มีการเพิ่ม inline script
  • การวัดประสิทธิภาพ: มีการปรับโครงสร้าง render batching แล้ว แต่เป้าหมาย “zero forced layouts per frame” ในแผนยังต้องยืนยันด้วย Chromium recording จริง

ประเด็นจาก audit ทั้ง 25 รายการและประเด็นใหม่ทั้ง 6 รายการจากแผน validation ที่อนุมัติ ได้รับการแก้ไขหรือคงผลการตรวจเดิมไว้พร้อมเหตุผลที่ชัดเจนและมีการทดสอบรองรับ กลุ่มข้อผิดพลาดที่มีผลกระทบสูงสุด 3 เรื่อง ได้แก่ การปัดเศษตัวเลขโดยไม่แจ้ง, ความไม่ตรงกันระหว่าง exponent กับ display และการเปลี่ยน token เมื่อ evaluation ล้มเหลว ได้รับการแก้ไขและมี regression tests แล้ว ส่วน Accessibility, storage, PWA lifecycle และ CI ได้รับการปรับให้ตรงกับสถาปัตยกรรมเป้าหมายของแผน โดยไม่เพิ่ม dependency หรือ build tooling

release นี้พร้อมเข้าสู่ขั้นตอนตรวจด้วยตนเองตามที่ระบุ ได้แก่ iPhone Safari/PWA และการวัด performance ด้วย DevTools ผล automated gates ผ่านทั้งหมดที่ 110 tests และ metadata ของเวอร์ชันซิงก์เป็น v7.12 ครบทั้ง 4 ตำแหน่ง อย่างไรก็ตาม การตรวจบนอุปกรณ์จริงและ performance recording ยังเป็นงานค้างก่อนยืนยันผลครบถ้วน
